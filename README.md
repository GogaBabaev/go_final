# Go Task Scheduler

Веб-приложение для управления задачами, разработанное на Go в рамках финального проекта курса «Go-разработчик» Яндекс Практикума.

Приложение позволяет создавать задачи, редактировать их, устанавливать правила повторения, отмечать выполнение и удалять задачи.

Данные хранятся в SQLite. Для взаимодействия с приложением используется REST API и готовый веб-интерфейс.

## Возможности

- Создание задач с датой, заголовком и комментарием.
- Редактирование существующих задач.
- Удаление задач.
- Отметка задач как выполненных.
- Автоматический перенос даты повторяющихся задач.
- Получение списка ближайших задач.
- Сортировка задач по дате.
- Поиск задач по заголовку, комментарию и дате.
- Аутентификация с использованием JWT.

## Технологии

- Go
- net/http
- SQLite
- database/sql
- JWT
- Docker

## Дополнительные задания

В проекте реализованы задания повышенной сложности:

1. Поддержка дополнительных правил повторения задач:
   - `w` — повторение по дням недели;
   - `m` — повторение по дням месяца.
2. Поиск задач по заголовку, комментарию и конкретной дате.
3. Аутентификация с использованием JWT и middleware.
4. Сборка и запуск приложения в Docker.

## Локальный запуск

Для запуска необходимо установить Go.

Клонировать репозиторий и перейти в директорию проекта:

```bash
git clone <URL_РЕПОЗИТОРИЯ>
cd go_final
```

Установить зависимости:

```bash
go mod download
```

Запустить сервер:

```bash
go run .
```

По умолчанию приложение доступно по адресу:

http://localhost:7540

При первом запуске SQLite-база данных создаётся автоматически.

### Переменные окружения

Приложение поддерживает следующие переменные окружения:

| Переменная | Назначение | Значение по умолчанию |
|---|---|---|
| `TODO_PORT` | Порт HTTP-сервера | `7540` |
| `TODO_DBFILE` | Путь к SQLite-базе | `scheduler.db` |
| `TODO_PASSWORD` | Пароль для доступа к приложению | Не задан |

Пример запуска с параметрами:

```bash
TODO_PORT=7540 TODO_DBFILE=scheduler.db TODO_PASSWORD=12345 go run .
```

Если `TODO_PASSWORD` не задана или пуста, аутентификация отключена.

Если пароль установлен, необходимо открыть:

http://localhost:7540/login.html

После успешного входа сервер возвращает JWT, который используется для доступа к защищённым API-запросам.

## API

Основные маршруты приложения:

| Метод | Маршрут | Описание |
|---|---|---|
| POST | `/api/task` | Создание задачи |
| GET | `/api/task?id=1` | Получение задачи |
| PUT | `/api/task` | Редактирование задачи |
| DELETE | `/api/task?id=1` | Удаление задачи |
| GET | `/api/tasks` | Получение списка задач |
| GET | `/api/tasks?search=текст` | Поиск задач |
| POST | `/api/task/done?id=1` | Отметка выполнения |
| POST | `/api/signin` | Аутентификация |
| GET | `/api/nextdate` | Расчёт следующей даты |

## Тестирование

Тесты находятся в директории `tests`.

Перед запуском необходимо запустить сервер:

```bash
go run .
```

В другом терминале выполнить:

```bash
go test -count=1 ./tests
```

Параметры тестирования находятся в `tests/settings.go`.

```go
var Port = 7540
var DBFile = "../scheduler.db"
var FullNextDate = true
var Search = true
var Token = ``
```

- `Port` — порт запущенного сервера.
- `DBFile` — путь к SQLite-базе относительно директории тестов.
- `FullNextDate = true` — проверка дополнительных правил повторения.
- `Search = true` — проверка поиска задач.
- `Token` — JWT для тестирования при включённой аутентификации.

Если `TODO_PASSWORD` не задан, `Token` можно оставить пустым.

Если аутентификация включена, необходимо получить JWT через `/api/signin` и указать его в `Token`.

**Внимание:** тесты могут изменять и удалять задачи в базе данных. Рекомендуется использовать отдельную тестовую базу.

## Docker

Для сборки Docker-образа выполнить:

```bash
docker build -t go-scheduler .
```

Создать директорию для хранения SQLite:

```bash
mkdir -p data
```

Запустить контейнер:

```bash
docker run --rm \
  --name go-scheduler \
  -p 7540:7540 \
  -v "$(pwd)/data:/data" \
  -e TODO_DBFILE=/data/scheduler.db \
  go-scheduler
```

После запуска приложение доступно по адресу:

http://localhost:7540

Директория `data` подключается к контейнеру через bind mount.

База данных сохраняется на хосте и не удаляется при остановке или пересоздании контейнера.

### Docker с аутентификацией

Для запуска с паролем:

```bash
docker run --rm \
  --name go-scheduler \
  -p 7540:7540 \
  -v "$(pwd)/data:/data" \
  -e TODO_DBFILE=/data/scheduler.db \
  -e TODO_PASSWORD=12345 \
  go-scheduler
```

Пароль `12345` приведён исключительно для примера. Для реального использования следует выбрать надёжный пароль.
